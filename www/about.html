webserv.

Un serveur HTTP/1.1 écrit en C++98, conçu dans le cadre du cursus 42. Connexions concurrentes, boucle événementielle non-bloquante via epoll, support CGI, gestion de sessions par cookies — sans framework, sans bibliothèque externe.

C++98 HTTP/1.1 epoll 42 Lausanne CGI Sessions
fonctionnalités
01

I/O non-bloquant

Boucle événementielle basée sur epoll en mode level-triggered. Toutes les connexions sont gérées dans un seul thread sans busy-loop.

02

HTTP/1.1

GET, POST, DELETE — dont le chunked transfer encoding. Parsing complet des requêtes et réponses, headers, codes de statut.

03

Support CGI

Exécution de scripts Python et PHP via fork/execve. Communication par pipes enregistrés dans epoll.

04

Config nginx-style

Virtual hosts, location blocks, redirections, autoindex, pages d'erreur personnalisées — syntaxe inspirée de nginx.

05

Upload de fichiers

Upload via POST avec directive upload_store. Destination indépendante de la racine du serveur.

06

Sessions & Cookies

Gestion de sessions en mémoire. Lecture du header Cookie, émission de Set-Cookie, login/logout.

configuration

Syntaxe
nginx-inspirée.

Le fichier de configuration suit une syntaxe familière aux utilisateurs de nginx. Plusieurs blocs server peuvent coexister.

  • listen — port d'écoute
  • root — répertoire racine
  • index — fichier par défaut
  • error_page — pages d'erreur personnalisées
  • cgi_pass — interpréteur CGI par extension
  • return — redirections 301/302
  • autoindex — listing de répertoire
# config/default.conf
http {
  server {
    listen      8080
    server_name localhost
    root        www/
    error_page  404 /errors/404.html

    location / {
      allowed_methods "GET|POST"
      autoindex on
    }

    location /cgi-bin {
      allowed_methods "GET|POST"
      cgi_pass .py  /usr/bin/python3
      cgi_pass .php /usr/bin/php-cgi
    }

    location /oldPage {
      return 301 /newPage
    }
  }
}
